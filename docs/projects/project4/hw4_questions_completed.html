Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring preference. Instead of asking people to rate every item on a 1 to 10 scale, MaxDiff asks people to make trade-offs. On each screen, a respondent sees a small set of items and chooses the one they like most and the one they like least.

This is useful because people are usually better at choosing between options than at using a numeric rating scale consistently. One person may give many 9s and 10s, while another person may be stricter and give mostly 6s and 7s. MaxDiff reduces that problem because it forces real differentiation.

In this assignment, the items are the core MSBA classes. I estimate class preferences in three ways:

  1. A simple counts analysis: percent picked best minus percent picked worst.
  2. A multinomial logit model estimated by maximum likelihood.
  3. The same multinomial logit model estimated with a Bayesian Metropolis-Hastings sampler.

My expectation is that the three methods should mostly agree on the strongest and weakest classes. The middle of the ranking may move around more because the differences between those classes are smaller.

Counts Analysis

The simplest analysis is the counts score. For each class, I calculate how often it was selected as best and how often it was selected as worst, relative to the number of times it was shown. The score is:

\[ \text{score}_j = \%\text{best}_j - \%\text{worst}_j \]

A positive score means the class was more often chosen as best than worst. A negative score means the class was more often chosen as worst than best.

From MaxDiff Data to MNL Choices

For the MNL model, each class gets a utility coefficient, \(\beta_j\). A higher coefficient means the class is more preferred.

For a task showing four classes, the probability that class \(j\) is chosen as best is:

\[ P(\text{best}=j) = \frac{\exp(\beta_j)}{\sum_{k \in \text{shown}} \exp(\beta_k)} \]

After the best item is chosen, the worst item is modeled from the remaining three classes using flipped utility. A high-utility item should be unlikely to be chosen as worst, so the worst-choice probability uses \(-\beta_j\):

\[ P(\text{worst}=j \mid \text{best chosen}) = \frac{\exp(-\beta_j)}{\sum_{k \in \text{shown except best}} \exp(-\beta_k)} \]

One technical issue is identification. Adding the same constant to every \(\beta\) does not change the choice probabilities. To solve this, I set item 1 as the reference class with \(\beta_1 = 0\) and estimate the other nine coefficients.

Code 
K = J - 1  # estimate beta_2 through beta_10; beta_1 is fixed at 0

def full_beta(beta_free):
    """Insert reference beta_1 = 0."""
    return np.r_[0.0, np.asarray(beta_free)]

def log_likelihood(beta_free):
    """Vectorized MaxDiff log-likelihood."""
    beta = full_beta(beta_free)
    v = beta[shown_mat]  # n_tasks x 4

    best_part = beta[best_idx] - logsumexp(v, axis=1)

    # For the worst choice, remove the item already picked as best.
    remaining_mask = shown_mat != best_idx[:, None]
    neg_v_remaining = np.where(remaining_mask, -v, -np.inf)
    worst_part = -beta[worst_idx] - logsumexp(neg_v_remaining, axis=1)

    return float(np.sum(best_part + worst_part))

def neg_log_likelihood(beta_free):
    return -log_likelihood(beta_free)

def log_likelihood_grad(beta_free):
    """Gradient of the log-likelihood for beta_2 through beta_10."""
    beta = full_beta(beta_free)
    v = beta[shown_mat]

    # Best choice contribution: chosen best minus softmax over shown items.
    p_best = np.exp(v - logsumexp(v, axis=1, keepdims=True))
    grad = np.zeros(J)
    np.add.at(grad, best_idx, 1.0)
    for col in range(shown_mat.shape[1]):
        np.add.at(grad, shown_mat[:, col], -p_best[:, col])

    # Worst choice contribution: chosen worst gets -1; remaining items get softmax over -utility.
    remaining_mask = shown_mat != best_idx[:, None]
    neg_v_remaining = np.where(remaining_mask, -v, -np.inf)
    p_worst = np.exp(neg_v_remaining - logsumexp(neg_v_remaining, axis=1, keepdims=True))
    np.add.at(grad, worst_idx, -1.0)
    for col in range(shown_mat.shape[1]):
        np.add.at(grad, shown_mat[:, col], p_worst[:, col])

    return grad[1:]

def neg_log_likelihood_grad(beta_free):
    return -log_likelihood_grad(beta_free)

MNL via Maximum Likelihood

The log-likelihood sums the probability of the observed best and worst choices across all tasks:

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[\beta_{j_b^*} - \log \sum_{j \in \text{shown}} \exp(\beta_j) - \beta_{j_w^*} - \log \sum_{j \in \text{shown} \setminus j_b^*} \exp(-\beta_j) \right] \]

I maximize this log-likelihood using numerical optimization.

Code 
mle = minimize(
    neg_log_likelihood,
    x0=np.zeros(K),
    jac=neg_log_likelihood_grad,
    method="BFGS",
    options={"gtol": 1e-6, "maxiter": 1000}
)

mle_success = mle.success
mle_message = mle.message
beta_mle_free = mle.x
beta_mle = full_beta(beta_mle_free)

# Approximate covariance matrix from the inverse Hessian returned by BFGS.
# Item 1 is fixed, so its SE is 0 by construction.
cov_free = np.asarray(mle.hess_inv)
se_free = np.sqrt(np.diag(cov_free))
se_mle = np.r_[0.0, se_free]

MNL via Bayesian Estimation

The Bayesian model uses the same MNL likelihood, but adds a prior distribution on the coefficients. I use a weakly informative normal prior:

\[ \boldsymbol{\beta} \sim N(0, 10I) \]

This prior is wide enough to let the data drive the result, but it also prevents absurdly large estimates. I estimate the posterior distribution using a random-walk Metropolis-Hastings sampler.

Code 
prior_sd = np.sqrt(10)

def log_prior(beta_free):
    return np.sum(-0.5 * (beta_free / prior_sd) ** 2 - np.log(prior_sd * np.sqrt(2 * np.pi)))

def log_posterior(beta_free):
    return log_likelihood(beta_free) + log_prior(beta_free)

def mh_sampler(beta0, n_iter=15000, step=0.18):
    beta = np.asarray(beta0).copy()
    draws = np.zeros((n_iter, len(beta)))
    lp = log_posterior(beta)
    accept = 0
    for t in range(n_iter):
        beta_star = beta + np.random.normal(0, step, size=len(beta))
        lp_star = log_posterior(beta_star)
        if np.log(np.random.rand()) < lp_star - lp:
            beta = beta_star
            lp = lp_star
            accept += 1
        draws[t, :] = beta
    return draws, accept / n_iter

Discussion

The substantive result is that students do not view all MSBA classes equally. Some courses are clearly more preferred, while others are more often selected as least preferred. This is useful information for understanding student interest, but it should not be interpreted as a perfect measure of course quality. Students may choose based on instructor reputation, topic familiarity, career goals, or how difficult they expect a class to be.

The three methods answer the same general question in different ways. Counts analysis is the best quick summary. It is easy to explain on a dashboard because it only uses best and worst percentages. MLE MNL is stronger when we want a formal model and standard errors. Bayesian MNL is useful when we care about uncertainty in derived quantities, such as preference shares, or when we want to extend the model later to estimate individual-level preferences.

There are also caveats. The survey respondents are a self-selected sample of MSBA students, so the results may not generalize to all future students. The timing of the survey matters too. Students who have already taken a class may judge it differently from students who only know the course title. Presentation order and recent conversations with classmates could also influence choices.

If I had more time, I would explore individual-level heterogeneity. For example, students interested in marketing analytics may rank the classes differently from students focused on engineering, product analytics, or consulting. A hierarchical Bayesian model would be a natural next step because it could estimate both the overall ranking and each student’s personal preference pattern.

## Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring preference. Instead of asking people to rate every item on a 1 to 10 scale, MaxDiff asks people to make trade-offs. On each screen, a respondent sees a small set of items and chooses the one they like most and the one they like least.

This is useful because people are usually better at choosing between options than at using a numeric rating scale consistently. One person may give many 9s and 10s, while another person may be stricter and give mostly 6s and 7s. MaxDiff reduces that problem because it forces real differentiation.

In this assignment, the items are the core MSBA classes. I estimate class preferences in three ways:

1. A simple counts analysis: percent picked best minus percent picked worst.
2. A multinomial logit model estimated by maximum likelihood.
3. The same multinomial logit model estimated with a Bayesian Metropolis-Hastings sampler.

My expectation is that the three methods should mostly agree on the strongest and weakest classes. The middle of the ranking may move around more because the differences between those classes are smaller.

## Counts Analysis

The simplest analysis is the counts score. For each class, I calculate how often it was selected as best and how often it was selected as worst, relative to the number of times it was shown. The score is:

$$
\text{score}_j = \%\text{best}_j - \%\text{worst}_j
$$

A positive score means the class was more often chosen as best than worst. A negative score means the class was more often chosen as worst than best.

## From MaxDiff Data to MNL Choices

For the MNL model, each class gets a utility coefficient, $\beta_j$. A higher coefficient means the class is more preferred.

For a task showing four classes, the probability that class $j$ is chosen as best is:

$$
P(\text{best}=j) = \frac{\exp(\beta_j)}{\sum_{k \in \text{shown}} \exp(\beta_k)}
$$

After the best item is chosen, the worst item is modeled from the remaining three classes using flipped utility. A high-utility item should be unlikely to be chosen as worst, so the worst-choice probability uses $-\beta_j$:

$$
P(\text{worst}=j \mid \text{best chosen}) = \frac{\exp(-\beta_j)}{\sum_{k \in \text{shown except best}} \exp(-\beta_k)}
$$

One technical issue is identification. Adding the same constant to every $\beta$ does not change the choice probabilities. To solve this, I set item 1 as the reference class with $\beta_1 = 0$ and estimate the other nine coefficients.

```{python}
#| label: likelihood-functions

K = J - 1  # estimate beta_2 through beta_10; beta_1 is fixed at 0

def full_beta(beta_free):
    """Insert reference beta_1 = 0."""
    return np.r_[0.0, np.asarray(beta_free)]

def log_likelihood(beta_free):
    """Vectorized MaxDiff log-likelihood."""
    beta = full_beta(beta_free)
    v = beta[shown_mat]  # n_tasks x 4

    best_part = beta[best_idx] - logsumexp(v, axis=1)

    # For the worst choice, remove the item already picked as best.
    remaining_mask = shown_mat != best_idx[:, None]
    neg_v_remaining = np.where(remaining_mask, -v, -np.inf)
    worst_part = -beta[worst_idx] - logsumexp(neg_v_remaining, axis=1)

    return float(np.sum(best_part + worst_part))

def neg_log_likelihood(beta_free):
    return -log_likelihood(beta_free)

def log_likelihood_grad(beta_free):
    """Gradient of the log-likelihood for beta_2 through beta_10."""
    beta = full_beta(beta_free)
    v = beta[shown_mat]

    # Best choice contribution: chosen best minus softmax over shown items.
    p_best = np.exp(v - logsumexp(v, axis=1, keepdims=True))
    grad = np.zeros(J)
    np.add.at(grad, best_idx, 1.0)
    for col in range(shown_mat.shape[1]):
        np.add.at(grad, shown_mat[:, col], -p_best[:, col])

    # Worst choice contribution: chosen worst gets -1; remaining items get softmax over -utility.
    remaining_mask = shown_mat != best_idx[:, None]
    neg_v_remaining = np.where(remaining_mask, -v, -np.inf)
    p_worst = np.exp(neg_v_remaining - logsumexp(neg_v_remaining, axis=1, keepdims=True))
    np.add.at(grad, worst_idx, -1.0)
    for col in range(shown_mat.shape[1]):
        np.add.at(grad, shown_mat[:, col], p_worst[:, col])

    return grad[1:]

def neg_log_likelihood_grad(beta_free):
    return -log_likelihood_grad(beta_free)

# Small check: the likelihood at zero is finite.
log_likelihood(np.zeros(K))
```

## MNL via Maximum Likelihood

The log-likelihood sums the probability of the observed best and worst choices across all tasks:

$$
\ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[\beta_{j_b^*} - \log \sum_{j \in \text{shown}} \exp(\beta_j) - \beta_{j_w^*} - \log \sum_{j \in \text{shown} \setminus j_b^*} \exp(-\beta_j) \right]
$$

I maximize this log-likelihood using numerical optimization.

```{python}
#| label: mle-fit

mle = minimize(
    neg_log_likelihood,
    x0=np.zeros(K),
    jac=neg_log_likelihood_grad,
    method="BFGS",
    options={"gtol": 1e-6, "maxiter": 1000}
)

mle_success = mle.success
mle_message = mle.message
beta_mle_free = mle.x
beta_mle = full_beta(beta_mle_free)

# Approximate covariance matrix from the inverse Hessian returned by BFGS.
# Item 1 is fixed, so its SE is 0 by construction.
cov_free = np.asarray(mle.hess_inv)
se_free = np.sqrt(np.diag(cov_free))
se_mle = np.r_[0.0, se_free]

shares_mle = np.exp(beta_mle) / np.exp(beta_mle).sum()
```

## MNL via Bayesian Estimation

The Bayesian model uses the same MNL likelihood, but adds a prior distribution on the coefficients. I use a weakly informative normal prior:

$$
\boldsymbol{\beta} \sim N(0, 10I)
$$

This prior is wide enough to let the data drive the result, but it also prevents absurdly large estimates. I estimate the posterior distribution using a random-walk Metropolis-Hastings sampler.

```{python}
#| label: bayes-functions

prior_sd = np.sqrt(10)

def log_prior(beta_free):
    return np.sum(-0.5 * (beta_free / prior_sd) ** 2 - np.log(prior_sd * np.sqrt(2 * np.pi)))

def log_posterior(beta_free):
    return log_likelihood(beta_free) + log_prior(beta_free)

def mh_sampler(beta0, n_iter=15000, step=0.18):
    beta = np.asarray(beta0).copy()
    draws = np.zeros((n_iter, len(beta)))
    lp = log_posterior(beta)
    accept = 0
    for t in range(n_iter):
        beta_star = beta + np.random.normal(0, step, size=len(beta))
        lp_star = log_posterior(beta_star)
        if np.log(np.random.rand()) < lp_star - lp:
            beta = beta_star
            lp = lp_star
            accept += 1
        draws[t, :] = beta
    return draws, accept / n_iter
```

## Discussion

The substantive result is that students do not view all MSBA classes equally. Some courses are clearly more preferred, while others are more often selected as least preferred. This is useful information for understanding student interest, but it should not be interpreted as a perfect measure of course quality. Students may choose based on instructor reputation, topic familiarity, career goals, or how difficult they expect a class to be.

The three methods answer the same general question in different ways. Counts analysis is the best quick summary. It is easy to explain on a dashboard because it only uses best and worst percentages. MLE MNL is stronger when we want a formal model and standard errors. Bayesian MNL is useful when we care about uncertainty in derived quantities, such as preference shares, or when we want to extend the model later to estimate individual-level preferences.

There are also caveats. The survey respondents are a self-selected sample of MSBA students, so the results may not generalize to all future students. The timing of the survey matters too. Students who have already taken a class may judge it differently from students who only know the course title. Presentation order and recent conversations with classmates could also influence choices.

If I had more time, I would explore individual-level heterogeneity. For example, students interested in marketing analytics may rank the classes differently from students focused on engineering, product analytics, or consulting. A hierarchical Bayesian model would be a natural next step because it could estimate both the overall ranking and each student's personal preference pattern.
